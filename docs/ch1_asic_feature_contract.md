# Chapter 1 ASIC Feature Contract

## Purpose

This note freezes the authoritative ASIC Chapter 1 primary feature contract for later ASIC->MIMIC alignment. The contract is recovered from the current Chapter 1 code/config plus the current run-config-resolved ASIC blocked schema, with the current frozen ASIC implementation treated as authoritative over older documentation.

## Boundary

This artifact fixes the contract at the **primary model-ready representation** written as `chapter1_primary_model_ready_dataset`, not at later model-specific feature filtering. In the current codebase, downstream logistic/XGBoost/feedforward baselines further reduce this representation to the 31 primary `*_median` columns, but that medians-only selection happens after model-ready construction and is therefore recorded here as a downstream selection rule rather than as the primary preprocessing contract itself.

## Recovery Method

1. Loaded `config/ch1_run_config.json` and resolved the active ASIC harmonized input root used by the Chapter 1 pipeline.
2. Loaded `config/ch1_feature_sets.json` and rebuilt the current feature-set definition through `build_chapter1_feature_set_definition(...)` against the live blocked ASIC schema and retained-stay table.
3. Verified the realized primary model-ready column layout by building the current `primary` model-ready dataset from the active input root.
4. Traced non-feature columns back to `instances.py`, `labels.py`, `splits.py`, `carry_forward.py`, `model_ready.py`, and `observation_process.py` to separate predictive variables from implementation/QC columns and secondary branches.

## Shared-Primary Features

The authoritative shared-primary representation contains **186 derived predictive columns**: **31 primary base variables x 6 statistics** (`obs_count`, `mean`, `median`, `min`, `max`, `last`).

All configured primary base variables are present in the current frozen blocked ASIC schema, and all have retained-data presence under the current Chapter 1 cohort. The current downstream baselines later keep only these **31 median columns** from the shared-primary block:

`albumin_median, base_excess_art_median, bicarbonate_art_median, bilirubin_total_median, core_temp_median, creatinine_median, crp_median, dbp_median, etco2_median, fio2_median, heart_rate_median, hematocrit_median, hemoglobin_median, inr_median, lactate_art_median, map_median, paco2_median, pao2_median, peep_median, pf_ratio_median, ph_art_median, platelets_median, ptt_median, resp_rate_median, sao2_median, sbp_median, spo2_median, urea_median, vt_median, vt_per_kg_ibw_median, wbc_median`

## Implementation-Only Variables

The primary model-ready table also contains **132 implementation-only columns**. These are not part of the shared predictive contract. They exist only to support:

- instance keys and block timing
- censoring and valid-instance checks
- proxy label construction and labelability bookkeeping
- train/validation/test split annotation
- carry-forward provenance and QC flags

## Secondary/Sensitivity-Only Variables

The current repo also materializes **99 secondary-only variables** that are not part of the shared-primary contract:

- **90 extended-additional derived feature columns** from the `extended` feature-set branch (`pct`, `il6`, `bnp`, `ntprobnp`, `ast`, `alt`, `ldh`, `amylase`, `lipase`, `troponin`, `ck`, `ck_mb`, `lymph_abs`, `lymph_pct`, `d_dimer` with the same six statistics)
- **9 observation-process variables** exported separately and optionally merged into `chapter1_primary_model_ready_with_observation_process.csv`

These variables are generated by the current codebase, but they are explicitly outside the shared-primary feature contract that should anchor later ASIC->MIMIC alignment.

## Unresolved Ambiguities

- The only material boundary choice is whether later ASIC->MIMIC work should align to the full **186-column primary model-ready representation** or to the narrower **31-column medians-only baseline subset**. This note freezes the former because issue 5.1.a1 is explicitly about the current preprocessing/model-ready contract, not later model-specific selection.
- Observation-process variables are generated in the current pipeline and can be merged into an optional model-ready export, but they are treated here as `secondary_only` because they are not part of `chapter1_primary_model_ready_dataset` and are already framed in the repo as an observation-process sensitivity layer.
